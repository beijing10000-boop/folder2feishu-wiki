# Folder2Feishu Drive v3 界面审计与设计规范

## 审计结论

旧版能够完成迁移，但页面采用高装饰深色视觉，存在侧栏与页头占用过多、卡片套卡片、英文技术标签混杂、状态优先级不清、长列表密度不稳定、异常与下一步操作距离较远等问题。对运维人员而言，最关键的“当前是否正常、哪里需要处理、任务进行到哪一步、下一步做什么”不能在首屏快速判断。

## v3 设计规范

- 风格：浅色企业运维控制台，克制、紧凑、优先可读性。
- 布局：桌面端固定左侧五步流程，顶部仅保留迁移方向、刷新、授权和版本；窄屏自动切换为顶部流程栏。
- 栅格：以 12 px 为基础间距，内容最大宽度 1440 px，表格与日志区域独立滚动。
- 字体：页面标题 28 px，模块标题 18 px，正文 14 px，辅助信息 12 px。
- 容器：8 px 圆角、1 px 中性边框、极轻阴影；减少卡片嵌套和重复标题。
- 颜色：蓝色表示主操作，绿色表示正常，橙色表示警告，红色只用于失败或危险操作。
- 按钮：主操作、普通操作、低优先级操作和危险操作四级；停止任务不与普通按钮同色。
- 状态：统一使用“正常、警告、异常、处理中、待验证、已停用”等中文状态，不以颜色作为唯一识别方式。
- 长任务：同时显示任务编号、阶段、总进度、数量、成功/失败/跳过/冲突、当前对象、耗时、心跳、工作线程、分片进度和增量日志。

## 页面级改动

1. 配置：集中配置与逐项验证，顶部给出 6 项完成度；来源与云盘目标形成单向路径。
2. 盘点：扫描状态、进度、文件/目录/容量指标、目录树和完整性问题在同一视图呈现。
3. 预检：阻断项与警告项分层，容量、权限、目录深度、同层节点等检查统一为预检矩阵。
4. 差异计划：摘要、动作列表、安全增量规则和最终确认分区，避免误触后直接写入。
5. 运行对账：任务状态与控制置顶，队列、分片、实时日志、失败项和对账证据分区展示。

## 交互反馈

- 所有提交按钮进入明确的忙碌态并阻止重复点击。
- 后台任务展示实时进度，页面刷新后从本地台账恢复。
- 网络超时、限流和远端错误显示中文原因、建议及重试入口。
- 长列表使用局部滚动、筛选和增量日志，避免整页持续增长。
- 页面刷新按钮只重取当前步骤数据，不把用户带回配置页。

## 不在本次范围

- 不调整迁移计算规则、权限校验、接口路径和数据库结构。
- 不处理旧版知识库数据；v3 使用独立运行目录和全新台账。
- 不增加移动端专用流程，只保证窄桌面窗口下不溢出。
